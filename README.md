## Objectif de sortie

Comprendre le trajet d'une requête, modifier une petite API, protéger une règle métier, sauvegarder des données et écrire un test utile. Le fil rouge commence par des produits, puis ajoute des commandes.

Le parcours distingue **Pratiquer**, **Comprendre** et **Repérer**. Les approfondissements se consultent au besoin ; ils ne constituent pas une seconde formation à suivre en parallèle.

La proposition dans `course/` conserve désormais exactement les repères 00 → 11 du workbook et sépare les ateliers. Elle sert de compagnon de lecture plus visuel, avec quelques vérifications ciblées, sans remplacer le contenu Markdown détaillé.

## Vérifier l'état du support

Consulte les [exécutions de validation](https://github.com/SimonGelbart/formation-dotnet/actions/workflows/formation.yml). Une exécution verte valide les exemples pour le commit testé. Elle ne valide pas les modifications de ton projet personnel ni tous les extraits théoriques.

Les tests, leurs limites et les commandes locales sont détaillés dans [VALIDATION.md](VALIDATION.md).
